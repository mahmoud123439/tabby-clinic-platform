# Tabby Clinic — منصة حجز وإدارة عيادات

منصة عربية باتجاه RTL لإدارة دليل الفروع والأطباء والمواعيد والطلبات، مع حسابات منفصلة للمرضى والإدارة والأطباء وموظفي الفروع، وملف طبي خاص للمريض.

## التشغيل السريع

### Windows

1. ثبّت Node.js 24 أو أحدث.
2. افتح PowerShell داخل مجلد المشروع وشغّل `.\run-local.ps1`.
3. افتح [http://127.0.0.1:3000](http://127.0.0.1:3000) واترك نافذة الخادم مفتوحة.
4. لإنشاء حساب الإدارة الأول، افتح نافذة PowerShell ثانية وشغّل `.\create-admin.ps1` واتبع التعليمات. لا يحتوي المشروع على كلمة مرور إدارة افتراضية.

### Linux / macOS

```sh
export CLINIC_DATA_KEY=$(node -p 'require("node:crypto").randomBytes(32).toString("base64")')
npm start
```

احفظ المفتاح في مدير أسرار آمن واستخدم المفتاح نفسه في كل تشغيل. على Windows، يتولى `run-local.ps1` إنشاء مفتاح محمي بـ DPAPI خارج مجلد المشروع.

## الوظائف

- تسجيل المريض وإنشاء ملفه الطبي تلقائيًا برقم ثابت بصيغة TBY-########؛ ملف المريض للقراءة فقط.
- الطبيب وموظفو الفرع ومديره والأدمن المخوّل يضيفون البيانات ويعدّلونها ضمن نطاق الفرع أو علاقة الرعاية.
- توثيق الأعراض والتاريخ الصحي والعلامات الحيوية والتقييم والتشخيص وخطة العلاج والتعليمات والمتابعة.
- رفع تقارير PDF وJPEG وPNG وDICOM مع حقول النتائج والوحدات والمدى المرجعي وبيانات الأشعة، وإظهارها للمريض مع المرفق.
- عرض الملف بتقسيم للبيانات الشخصية والتاريخ الصحي والزيارات والأدوية والتحاليل والأشعة والعمليات والمستندات والموافقات وسجل التدقيق.
- دليل تخصصات وفروع وأطباء، بحث حسب التخصص والموقع، جداول مواعيد وحجز ومنع تكرار الموعد.
- طلبات المستشفى والمنزل والاستشارات وتوصيل الدواء والتحاليل والأشعة مع متابعة الحالة. الأسعار غير معروضة حتى يؤكدها مقدم الخدمة.
- لوحة إدارة لإعداد الفروع والأطباء والخدمات ومراجعة الحجوزات والطلبات وإنشاء حسابات الموظفين والأطباء والمديرين.
- إدارة ملفات المرضى: الإدارة المركزية على مستوى المركز، وموظفو كل فرع على ملفات مرضاه المرتبطة بالفرع فقط، ويضيفون البيانات والسجلات والتقارير؛ المريض يقرأ الملف وينزّل تقاريره فقط. لكل ملف رقم طبي ثابت، وتُحفظ التغييرات وسجلات الوصول في سجل التدقيق.
- صلاحيات محددة بالدور والفرع، كلمات مرور مشتقة بـ PBKDF2، جلسات محمية، تشفير AES-256-GCM للبيانات الصحية والملفات، وسجل تدقيق.

## التهيئة والبيانات

قاعدة البيانات والمفتاح المحليان يُحفظان خارج المستودع. لا توجد بيانات أطباء أو منشآت فعلية مضمونة في المشروع. الفروع الخمسة المطلوبة (المعادي، التجمع الخامس، مدينة نصر، مصر الجديدة، الجيزة) وأسماء الأطباء وأسعار الكشف والتراخيص والجداول يجب إدخالها والتحقق منها بواسطة الجهة المشغلة قبل إظهارها أو استقبال حجوزات فعلية. لا ينشئ التطبيق ملفات وهمية لملء بيانات المرضى أو الأطباء.

المشروع ليس خدمة طبية أو نظامًا سريريًا جاهزًا للاستخدام العام. راجع [تعليمات التشغيل والحدود](OPERATIONS.md) و[إشعار البيانات المؤقت](PRIVACY.md) قبل أي استخدام، خصوصًا قبل إدخال بيانات صحية حقيقية.

## البنية

- `server.js`: خادم HTTP وواجهات API والمصادقة والتخزين المحلي.
- `index.html`, `app.js`, `data.js`, `patient-record.css`: واجهة الموقع ولوحات المستخدمين وتصميم الملف الطبي.
- `login.html`, `auth-page.js`: التسجيل وتسجيل الدخول.
- `scripts/bootstrap-admin.js`, `create-admin.ps1`: إنشاء حساب الإدارة الأول دون كلمة مرور افتراضية.
- `test/`: اختبارات API والصلاحيات والتدفقات الأساسية.
- `docs/`: قوالب إدخال الأطباء والموظفين وقرارات التصميم.
